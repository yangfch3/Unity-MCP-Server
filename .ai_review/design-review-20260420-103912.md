## 2. 自由评审意见

1. **`Console.SetOut` 存在进程级竞态条件**。`Console.Out` 是进程全局状态。`RunWithTimeout` 在主线程上调用 `Console.SetOut(writer)` 后启动后台线程，执行完再 `Console.SetOut(originalOut)` 恢复。如果在此期间有其他代码（如 Unity 内部日志、其他 tool 并发执行）也写 `Console.Out`，它们的输出会被错误捕获或丢失。考虑在后台线程内部使用 `TextWriter` 直接重定向，或使用 `StringWriter` 配合反射替换方法内的输出目标，避免修改全局 `Console.Out`。

2. **`thread.Join(timeout)` 同步阻塞主线程长达 10s**。虽然文档解释了与 `MainThreadQueue` 超时的兼容性，但这意味着在用户代码执行期间，**整个 Unity Editor 主循环被冻结**（无 Repaint、无 Update、无输入响应）。对于 10s 上限来说这是一个很差的用户体验。建议考虑：(a) 降低默认超时为 5s；(b) 使用 `Task.Run` + `await` 的异步等待模式而非同步 Join，让主线程在等待期间仍可响应。

3. **`Thread.Abort()` 在 .NET 生态中已被标记为过时且危险**。它可能导致 `finally` 块未执行、`lock` 未释放、CLR 内部状态损坏。虽然在 Mono 后端上比 CoreCLR 更可控，但仍应在文档中明确说明：这是一个"尽力而为"的安全网，不保证能干净终止所有代码（如非托管调用中的阻塞）。

4. **Response Builder 的设计决策值得保留但需要更简洁**。文档中第 179 行的"Wait —"自我修正段落展示了思考过程，但在最终设计文档中应精简为结论性描述，移除思考过程痕迹。

5. **缺少 `Description` 字段定义**。`IMcpTool` 接口要求 `Description` 属性，但文档中 Component 部分只列出了 `Name`、`Category`、`InputSchema`，遗漏了 `Description` 的内容。

## 3. 改进建议

### 🔴 关键问题（必须修改）

1. **`Console.SetOut` 竞态条件需设计规避方案** — 当前方案修改进程全局状态，在并发场景下不安全。建议方案：不修改全局 `Console.Out`，而是在编译后的代码入口方法中注入一个 `TextWriter` 参数，或者改为约定用户代码必须 `return string` 而非依赖 Console 输出。如果保留 Console 重定向，至少需要加锁确保同一时间只有一个 `code_executeImmediate` 在执行。

2. **添加验收标准** — 补充一个 Acceptance Criteria / Test Matrix 章节，至少覆盖：toggle OFF 返回 error、编译错误返回详情、无 `Run()` 方法返回错误、正常执行返回 output、超时返回 timeout error、运行时异常返回 stack trace。这也是 project-context 中 Testing Standards 的要求。

### 🟡 建议改进（推荐修改）

1. **添加 Out of Scope 章节** — 显式声明不支持的场景：异步用户代码（`async Run()`）、Unity API 调用（需主线程）、外部 NuGet 引用、多文件编译、返回值机制等。这能有效防止后续需求蔓延。

2. **主线程阻塞问题需有明确取舍说明** — 补充一段说明：`thread.Join(timeout)` 会冻结 Editor UI 最长 10s，这是当前设计的已知限制。可在未来版本中改为异步等待模式（`Task.Run` + `await`）来改善，但当前 MVP 选择同步方案以降低复杂度。

3. **补充 `Thread.Abort` 的风险说明与缓解措施** — 在 Thread Model Decision 中增加一段：`Thread.Abort()` 不保证干净终止（如非托管代码阻塞、finally 块问题），这是已知的 best-effort 行为。建议在超时提示中告知 Agent 建议重启 MCP Server 以确保状态干净。

4. **明确 `Description` 属性内容** — 在 Component 定义中补充 `Description` 字段的具体文案。

5. **清理 Response Builder 中的思考过程痕迹** — "Wait —" 段落改写为直接陈述最终设计决策。

### 🟢 锦上添花（可选优化）

1. **考虑对引用的程序集做白名单过滤** — 当前设计引用 `AppDomain.CurrentDomain.GetAssemblies()` 全部程序集，理论上编译出的代码可以做任何操作（文件删除、网络请求等）。虽然 toggle 默认 OFF 已是安全门控，但可以在文档中讨论未来是否需要更细粒度的沙箱机制。

2. **超时时间可配置化** — 10s 硬编码在某些场景（如大量数据处理）可能不够。可以考虑作为 `inputSchema` 的可选参数（`timeout`），或作为 EditorPrefs 配置项。
